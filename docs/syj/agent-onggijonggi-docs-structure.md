# docs/ 구조 가이드 — 왜 이렇게 나누고, 언제 무엇을 추가하나

> 이 문서는 `docs/` **폴더 자신의 설명서**다. 새 문서를 추가하기 전에 여기를 읽고, 아래 원칙 아래에서 추가한다.
> 참조 구현은 llmhub 프로젝트의 `docs/`이고, 아래 예시는 거기서 왔다.

---

## 1. 설계 축 2개

문서를 "주제별로" 나누면 금방 무너진다. 실제로 작동한 축은 두 개다.

### 축 1 — 번호 = 읽는 순서

`00`부터 순서대로 읽으면 **그게 곧 온보딩**이 되도록 번호를 붙인다. 숨은 분기점이 있다:

- **`00~04` = "무엇을 만드나"** (명세) — 정체성 → 구조 → 제약 → 데이터 → 품질
- **`05~08` = "어떻게 일하나"** (절차) — TDD → 메모리 → git → 자율성

### 축 2 — 쓰기 권한 = 진짜 분류 기준

가르는 진짜 기준은 주제가 아니라 **누가 쓸 수 있냐**다. 이게 문서 드리프트를 막는 핵심이다.

| 층 | 누가 쓰나 |
| --- | --- |
| 거버넌스·명세 (`00~08`, `requirements/` 본문) | **사람만.** 에이전트는 읽기 전용(체크박스 `- [ ]`→`- [x]`만 예외) |
| 누적 지식 (`LEARNINGS`, `OPEN-QUESTIONS`) | **에이전트가 append** |
| 산출물·소통 (`reviews/`, 참고 지도) | 자유 |

**이 축이 서려면 각 문서 머리에 "누가 고칠 수 있는지"를 적어야 한다.** 안 적으면 무너진다.

| `02-decisions` | **결정·경계 = 구현 제약** | 사람 |

## 3. 전이 가능한 원칙 (구조보다 이게 자산)

1. **문서가 세션 메모리다.** 세션 시작 시 `LEARNINGS` + `OPEN-QUESTIONS`를 읽고 출발한다. 컨텍스트가 날아가도 지식이 남는다.
2. **경계는 한 줄로 못 박는다** — *아직 하거나 정할 일이 남았으면 → `OPEN-QUESTIONS`. 남은 게 없는 확정 사실이면 → `LEARNINGS`.* 이 줄이 없으면 둘 다 쓰레기통이 된다.
3. **결정 문서는 참고가 아니라 제약이다.** 어겨야 할 것 같으면 코드를 짜지 말고 **질문**한다.
4. **지도이지 소스가 아니다.** 참고 문서 머리에 이걸 못 박고, 값·동작은 **반드시 실제 코드**에서 확정한다. 문서가 코드와 어긋나는 순간 함정이 된다.
5. **`CLAUDE.md`는 요약, `docs/`는 전문.** 항상 로딩되는 곳엔 요약만 두고 상세는 여기로 내린다. **같은 내용을 양쪽에 복사하지 않는다** — 포인터로 가리킨다.
6. **시점 산출물은 날짜-범위 네이밍** (`reviews/2026-07-11-full-codebase.md`).
7. **쓰기 권한을 문서에 명시한다** (축 2).

## 4. 언제 무엇을 추가하나 (성장 경로)

**필요해질 때 만든다. 미리 만들지 않는다.**

| 트리거 | 추가할 것 |
| --- | --- |
| 세션 간 지식이 새기 시작할 때 (**가장 먼저 값을 함**) | `LEARNINGS` · `OPEN-QUESTIONS` |
| v0 스코프가 합의될 때 | `00-overview` |
| 구조 설명을 두 번 이상 반복하게 될 때 | `01-architecture` |
| 모듈이 생길 때 | `requirements/REQ-*` |
| 뒤집기 비싼 결정이 쌓일 때 | `02-decisions` |
| 리뷰를 실제로 돌릴 때 | `reviews/` |

**만들지 말 것:** 지킬 코드가 없는데 절차 문서(`05`·`06`·`08`)부터 만드는 것 — 형식만 남고 아무도 안 지킨다.

## 5. 추가할 때 지킬 것

- **확인 안 된 건 스텁으로.** 지어내지 않는다. 빈 자리가 틀린 내용보다 낫다.
- **짧게.** 길면 안 읽힌다.
- **중복 금지.** `CLAUDE.md` ↔ `docs/` 복사 대신 포인터.

## 6. 최소 형식 (추가할 때 이 모양으로)

**`LEARNINGS.md`** — append-only. "코드 읽으면 아는 것"·git 히스토리·추측은 넣지 않는다.

```
### YYYY-MM-DD · <한 줄 제목>
- **사실:** 무엇이 참인가
- **근거:** 어떻게 확인했나 (실행 결과·로그·링크)
- **영향:** 앞으로 무엇을 다르게 하나
```

**`OPEN-QUESTIONS.md`** — 상태: `OPEN` · `RESOLVED`(커밋 sha 남김) · `WONTFIX`.

```
### OQ-NNN · <한 줄 제목>  [OPEN]
- **맥락:** 왜 생겼나
- **결정할 것:** 무엇을 정해야 하나
- **선택지:** (있으면)
- **다시 볼 시점:** 언제 / 무엇이 트리거인가
```

**`00-overview.md`** — 정체성 / 현재 상태 / 스코프 / 지금 하지 않는 것

**`01-architecture.md`** — "지도이지 소스가 아니다" 머리말 / 구조 / 요청 흐름 / 연동 지점 표 / 예정(코드 없는 것)
