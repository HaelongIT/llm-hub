# llmhub 교훈 이관 번들 → 옹기종기

llmhub을 세우며 쌓인 **구현 교훈(`docs/LEARNINGS.md`)** 을 옹기종기로 옮기기 위한 번들이다.
DB 설계(`../db-design-for-onggijonggi/`)·인프라(`../infra-for-onggijonggi/`) 번들의 후속이다.

```
learnings-for-onggijonggi/
├─ README.md              ← 지금 이 파일
├─ trap-map.md            ← ★ 핵심. 함정·교훈 지도 81항목 / 8묶음
└─ reference/
   └─ LEARNINGS.md        ← llmhub 원문 그대로 (바이트 동일)
```

---

## 먼저: 원문 파일 하나만 가져가면 왜 부족한가

`LEARNINGS.md`는 llmhub **자기 자신을 위해** 쓴 로그다. 그래서 자기 프로젝트의 문서 체계에 깊이 물려 있다.

| 사실 | 수치 |
|---|---|
| 원문 분량 | 510줄 · 항목 **65개** (2026-07-10 ~ 07-13) |
| 본문에 박힌 설계코드 참조 | **215회** |
| 그중 `R-`·`L-`·`F`·`B` (llmhub `docs/reviews/` 두 파일에만 정의됨) | **약 71회** |
| 나머지가 가리키는 곳 | `docs/02`(결정) · `docs/04`(비기능) · `docs/01`(아키텍처) · `OPEN-QUESTIONS.md`(589줄) · `docs/08` |

그래서 원문만 받으면 이런 줄들이 통째로 뜻을 잃는다.

> **영향:** S15, E16, REL-5
> **F1 — Reactor `flatMapMany` 매퍼는 upstream onNext에서만 실행된다.** 그래서 감사 `doFinally`를 …

게다가 본문이 llmhub 클래스·파일명(`Blocking.call`, `IdxProperties`, `ElasticsearchChunkRepository`,
`lib/ui-message-stream.ts`)을 직접 부른다. **옹기종기는 구현을 다시 짜므로 그 이름이 존재하지 않는다.**

그렇다고 나머지 문서를 다 넘기는 것도 답이 아니다 — `OPEN-QUESTIONS.md`는 llmhub의 WIP 상한·HALT 태그·항목별
상태 같은 **자기 거버넌스 상태**라 옹기종기엔 의미가 거의 없다.

**그래서 번역했다.** `trap-map.md`가 이 번들의 핵심 산출물이다.

---

## `trap-map.md` — 무엇을 어떻게 바꿨나

**81항목 / 8묶음.** 원문의 시간순 나열을 주제별로 다시 엮고, llmhub 전용 참조를 걷어냈다.

| 묶음 | 항목 수 | 무엇 |
|---|--:|---|
| 1. 조용한 실패 | 8 | 에러 없이 잘못되는 것 — 제일 값진 묶음 |
| 2. 보안·인가 | 14 | 통과하는 테스트가 숨긴 구멍 |
| 3. 리액티브·비동기 | 8 | WebFlux/Reactor |
| 4. 데이터·상태 정합성 | 9 | 두 저장소 · 색인 · 동시성 · 컨텍스트 |
| 5. 한국어·인코딩 | 5 | 언어 때문에만 터지는 것 |
| 6. 버전·의존성 선택 | 8 | 무엇을 고르고 무엇을 피할까 |
| 7. 테스트가 무엇을 강제하는가 | 13 | 기법 |
| 8. 컨테이너·기동·레포 위생 | 16 | 운영 |

**번역 규칙 (실제로 한 일):**

- **설계코드를 본문에서 없앴다.** `S`/`E`/`R-`/`L-`/`F`/`B`/`OQ`/`SEC`/`REL`/`PERF`/`MAINT`/`D-` → 뜻을 풀어
  쓰거나 삭제. 코드는 **출처 줄에만** 남겼다(원문 대조용).
- **llmhub 클래스명은 역할로 바꿨다.** `Blocking.call` → "블로킹 격리 래퍼" 식.
- **다만 프레임워크 실제 API 이름은 그대로 뒀다** — `subscribeOn`·`doFinally`·`DataBufferUtils.join`·
  `TokenTextSplitter`·`useChat` 등은 팀도 똑같이 쓰는 이름이라 바꾸면 오히려 못 찾는다.
- **항목 제목을 증상 문장으로 썼다.** 목차만 봐도 Ctrl+F가 먹는다.

**읽는 법 — 규칙이 아니라 증상으로.**
규칙 목록으로 읽으면 안 지켜지고, 증상 목록으로 읽으면 **그 상황이 왔을 때 알아본다.**
그래서 처음엔 목차만 훑고, 증상이 나타났을 때 해당 항목을 편다.
더 파고들 필요가 생기면 항목 끝 `> 원문:` 줄로 `reference/LEARNINGS.md`에서 전문을 찾는다.

**팀 프로젝트라면 [1-8](trap-map.md#1-8)을 먼저 본다** — Windows에서 실행 비트가 조용히 유실돼 **POSIX 클론에서
git 훅이 에러 없이 꺼지는** 함정이다. 사람이 늘어나는 순간 제일 먼저 터지는데 알아챌 신호가 없다.

## 무엇을 뺐나 (그리고 뭘 안 뺐나)

**빼려던 것보다 적게 뺐다.** 원문을 전수로 훑어 보니 llmhub 전용 프로세스 서술은 예상보다 적었고, 대부분은
다른 팀에도 그대로 유효했다.

**원문 65개 중 63개를 인용했다. 통째로 뺀 것은 2개다:**

| 뺀 항목 | 이유 |
|---|---|
| `PROCESS — 규칙을 실행 가능하게 만들자 문서 안의 모순이 드러났다` | llmhub 자체 문서(TDD·git 워크플로) 사이의 모순을 정리한 기록. 그 문서들을 안 넘기므로 옮길 대상이 없다 |
| `LOW 항목 마무리 — 고친 것과 v0 스코프로 남긴 것` | llmhub 코드리뷰 항목 12건의 처리 결과 목록. **단 이 중 보편적인 둘(업로드 MIME 스니핑·IdP 헬스체크)은 [2-11]·[8-2]로 따로 뽑았다** |

**부분만 가져온 것 3개** — 항목 전체가 아니라 그 안의 보편적 함정만 뽑았다:
`코드리뷰 수정 사이클 F1~F7`(개별 함정 5건은 수록, 사이클 서술은 제외) ·
`방향 A 후속 UI 다듬기`(한글 폰트·취소 UI만) ·
`재색인 대상 식별을 청킹 버전까지`(파생 쿼리 검증 교훈만, 승인 절차는 제외).

**한 항목만 출처가 다르다.** [8-7](trap-map.md#8-7)(`mem_limit`과 JVM 힙)은 `LEARNINGS.md`가 아니라 llmhub
`.env.example` 주석이 근거다. 그 항목의 출처 줄에 그렇게 적어 뒀다.

## 안 담은 것

- **교훈을 쌓는 규칙(llmhub `docs/06-memory-protocol.md`)** — 사용자 결정에 따라 **지식만** 옮긴다.
  참고로 llmhub은 기록을 셋으로 나눴다: 확정된 사실은 `LEARNINGS.md`, 아직 정할 게 남은 것은
  `OPEN-QUESTIONS.md`, 코드리뷰 결과는 `docs/reviews/`. 경계는 한 줄이었다 —
  *"아직 하거나 정해야 할 일이 남았으면 열린 질문, 남은 게 없는 확정된 사실이면 교훈."*
  **옹기종기의 기록 규칙은 팀이 정한다.**
- **`OPEN-QUESTIONS.md` · `docs/reviews/` 원문** — llmhub의 거버넌스 상태라 옮길 값이 낮다.
  (`trap-map.md`가 인용한 리뷰 발견들은 이미 본문에 풀어 썼다.)

## 경고

- 이 번들은 **llmhub의 특정 시점 스냅샷**이다(원문 최신 항목: 2026-07-13). 이후 llmhub이 바뀌어도
  **자동 동기화되지 않는다.**
- **기록 규칙을 함께 넘기지 않았으므로**, 이 문서는 옹기종기에서 **자라지 않는다.** 팀이 자기 교훈을 쌓을
  자리를 따로 만들지 않으면 여기서 굳는다.
- 버전 전제: Spring Boot 3.x + WebFlux · Spring AI 1.1.x · Elasticsearch 9.4.3(+nori) · PostgreSQL 17 ·
  Keycloak 26 · Next.js(App Router) + AI SDK v5. **다른 버전이면 증상은 대체로 유효하지만 처방의 세부는
  다시 확인**해야 한다.
- 지도의 항목은 전부 llmhub에서 **실제로 밟은 것**이고 출처가 달려 있다. 추측으로 채운 항목은 없다.
